# Claude Code закончил работу минуту назад, а ты всё ещё смотришь в соседнее окно

Уведомление macOS приходит, когда сессия закончила задачу, задала вопрос или показала план.
В подзаголовке — имя сессии, так что из десяти вкладок видно, какая именно освободилась.

```
claude plugin marketplace add https://github.com/beCyborg/jadlis-hub
claude plugin install jadlis-notifications@jadlis
```

Отдельно ставить обычно не нужно: плагин приезжает зависимостью `jadlis-claudecode`.
Ключей и подписок не нужно, патченый бинарь `darwin/arm64` лежит прямо в репозитории.

![Одинаковые вкладки, уведомление с именем сессии, клик поднимает нужную](docs/img/hero-jadlis-notifications.webp)

Текстом: слева десяток одинаковых вкладок, справа уведомление с именем сессии, и клик по нему
поднимает ту самую вкладку.

Это форк [claude-notifications-go](https://github.com/777genius/claude-notifications-go) под
GPL-3.0, выложенный как моё рабочее место, а не как продукт.

## Было → стало

| Без уведомлений | Апстримный плагин | Этот форк |
|---|---|---|
| **Как узнаёшь, что задача кончилась.** Переключаешься в терминал и смотришь сам. | Приходит уведомление «✅ Completed». | То же уведомление, но заголовки русские: «✅ Задача выполнена», «🔍 Ревью завершено», «❓ Есть вопрос», «📋 План готов». |
| **Какая именно сессия освободилась.** Никак — идёшь искать по вкладкам. | В подзаголовке `ветка · папка`: у трёх сессий в одном репозитории он одинаковый. | В подзаголовке реальное имя сессии из `custom-title.json` — то же, что видно в самом Claude Code. |
| **Что написано в теле.** — | К тексту дописывается хвост со счётчиками: `📝 1 new ▶ 2 cmds ⏱ 41s`. | Только текст резюме, хвост убран. |
| **Что происходит при фоновых агентах.** — | «Задача выполнена» прилетает на каждый промежуточный Stop, пока воркфлоу ещё работает. | Гейт считает незавершённые фоновые агенты и воркфлоу и глушит уведомление, пока их больше нуля. |
| **Как звучит.** — | Звук включён, в заголовке ещё и метка сессии. | Звук выключен, метка выключена, клик поднимает нужную вкладку iTerm2. |

## Как это работает

![Событие сессии, гейт фоновых задач, уведомление на экране, клик по уведомлению](docs/img/how-jadlis-notifications.webp)

На входе — событие сессии Claude Code.
Внутри — гейт считает незавершённые фоновые агенты и воркфлоу и держит уведомление, пока их
больше нуля.
На выходе — уведомление macOS, клик по которому поднимает вкладку этой сессии.

Текстом: событие сессии → гейт фоновых задач → уведомление на экране → клик поднимает ту самую
вкладку.

На входе — пять хуков Claude Code: `Stop`, `SubagentStop`, `PreToolUse` (на `ExitPlanMode`
и `AskUserQuestion`), `Notification` (на запрос разрешения) и `TeammateIdle`.
Внутри — `bin/hook-wrapper.sh` запускает Go-бинарь, тот разбирает событие и шлёт уведомление.
На выходе — нативное уведомление macOS с заголовком по статусу и подзаголовком-именем сессии.

Хук `Stop` идёт не напрямую, а через `bin/stop-gate.sh`. Гейт читает транскрипт сессии
(`bin/pending-bg-tasks.py`) и считает запущенные, но не завершённые фоновые агенты и воркфлоу.
Больше нуля — уведомление глушится, ноль — событие уходит в `hook-wrapper.sh` без изменений.
Любая ошибка счётчика равна нулю, то есть уведомление всё равно проходит. Запуск старше шести
часов без уведомления о завершении считается мёртвым, иначе гейт молчал бы вечно.
Лог решений — `${TMPDIR}/jadlis-notifications-stop-gate.log`, обрезается на 256 КБ.

Бинарь читает конфиг из `~/.claude/claude-notifications-go/config.json`, а если его нет — из
`config/config.json` плагина. Путь захардкожен в апстримном Go-коде и в форке намеренно не менялся,
так что уже существующий конфиг подхватывается как есть. Всё остальное, что звалось по имени
плагина, переехало в свой неймспейс (`~/.cache/jadlis-notifications/`,
`~/.claude/jadlis-notifications/`), так что апстримный плагин рядом ничему не мешает.

Если бинарь пропал или разошёлся по версии с `plugin.json`, `hook-wrapper.sh` скачивает его
из релиза `v<версия>` этого репозитория и сверяет sha256 — к апстриму он не ходит.

## Установка и первый запуск

**а) Текст для вставки агенту.** Скопируй целиком в чат Claude Code:

```
Ты — установщик. Поставь на этот Mac плагин jadlis-notifications из маркетплейса jadlis.
Ключей этому плагину не нужно, ничего секретного спрашивать не надо.
Выполни ровно эти команды, дословно, ничего не сокращая:
1. claude plugin marketplace add https://github.com/beCyborg/jadlis-hub
2. claude plugin install jadlis-notifications@jadlis
3. claude plugin list — покажи мне строку про jadlis-notifications и его версию.
Потом скажи мне одной строкой: перезапусти Claude Code, чтобы хуки подхватились.
Перед каждой командой покажи её мне целиком и дождись «да». Сказал «нет» — не выполняй,
скажи, что именно пропустил, и иди дальше.
Команда вернула ошибку — остановись, покажи вывод, к следующей не переходи.
```

**б) Команды руками.**

```
claude plugin marketplace add https://github.com/beCyborg/jadlis-hub
claude plugin install jadlis-notifications@jadlis
claude plugin list
```

Первая команда ничего не ставит — она добавляет маркетплейс. Ставит только вторая, и снимается
она одной строкой: `claude plugin uninstall jadlis-notifications@jadlis --keep-data`.

**в) Первый запуск.** Перезапусти Claude Code и дай сессии закончить любую задачу — уведомление
придёт само, отдельной команды у плагина нет. macOS в первый раз спросит разрешение на
уведомления: разреши, иначе всё уйдёт в никуда.

**г) Клик по уведомлению в iTerm2.** Точное попадание во вкладку требует iTerm2 Python API,
это один раз руками: iTerm2 → Settings → General → Magic → **Enable Python API**, потом
перезапустить iTerm2. Venv разворачивает `bin/install.sh` при установке; вручную это
`python3 -m venv ~/.claude/claude-notifications-go/iterm2-venv` и
`~/.claude/claude-notifications-go/iterm2-venv/bin/pip install iterm2`. Без Python API клик просто
поднимает iTerm2, не выбирая вкладку.

## Границы, стоимость, обновление

**Чего не делает.** Не работает нигде, кроме macOS на Apple Silicon: в релизе лежит только
`darwin/arm64`, остальные платформы апстрима не собираются. Не шлёт ничего в Telegram и Slack —
вебхуки в дефолтном конфиге выключены. Не заменяет собой чтение вывода: в теле только резюме
статуса. Не глушит уведомления по фоновым процессам вообще — гейт считает агентов и воркфлоу
Claude Code, а фоновый `Bash` намеренно не считается, иначе dev-сервер глушил бы всё навсегда.
Заголовки `session_limit_reached` и `api_error` остались английскими: в конфиге владельца их нет,
и форк ничего не придумывал.

**Что нужно.** Ключей и подписок не нужно. Нужен macOS с разрешением на уведомления. Для точного
клика по вкладке — iTerm2 с включённым Python API и `python3` в системе. Для гейта фоновых задач —
`python3` (берётся `/usr/bin/python3`, он есть в системе всегда).

**Порядок расхода токенов.** Нулевой: модель здесь не участвует вообще. Работают хуки и Go-бинарь,
токены не тратятся.

**Проверено там, где я работаю:** мой Mac, iTerm2 + tmux, Apple Silicon. Другого железа под рукой
нет, а в релизе и лежит только `darwin/arm64`.

**Лицензия.** Форк [claude-notifications-go](https://github.com/777genius/claude-notifications-go)
под GPL-3.0 — текст в файле [LICENSE](LICENSE); патчи перечислены в NOTICE.md.

**Обновление.** У стороннего маркетплейса авто-обновление на твоей стороне выключено: пока не
запустишь первую команду, у тебя остаётся та версия, которую ты поставил.

```
claude plugin marketplace update jadlis
claude plugin update jadlis-notifications@jadlis
claude plugin list
```

Переустановка, если что-то встало криво:

```
claude plugin uninstall jadlis-notifications@jadlis --keep-data && claude plugin install jadlis-notifications@jadlis
```

Подтянуть новую версию апстрима — `tools/sync-upstream.sh <версия>`: он вливает апстримный тег,
заново накладывает патчи форка, пересобирает бинарь, сверяет его версию и печатает команды релиза.
README апстрима лежит в [docs/UPSTREAM-README.md](docs/UPSTREAM-README.md).
